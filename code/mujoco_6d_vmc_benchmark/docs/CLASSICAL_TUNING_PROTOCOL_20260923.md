# 经典控制器固定预算开发搜索协议

本协议在新搜索启动前固定。目的是检验经典控制器参数是否造成当前失败，并建立可重复的参数选择流程；不是证明 proposed 优势，也不是论文 office blind test。

## 预算与候选

每家族 8 个候选 × 同一 3 个开发条件 = 24 个完整 24 s 回合，两家族合计 48。已有 K300/K900/r2 的历史结果另行报告，不从中额外挑选未纳入候选的获胜者。每个配置在三个条件上的所有失败都参与选择；执行错误不能视为低误差。

- 积分参考阻抗：笛卡尔平移 K ∈ {300, 600, 900, 1200} N/m，阻尼比 ζ ∈ {0.7, 1.2}，笛卡尔转动 Krot = K/20。虚拟质量 1 kg、惯量 0.08、nullspace damping 2，其余使用已有 MovingEquilibrium 默认参数。位置弹簧误差上限 0.04 m 对应 12–48 N 的弹簧力上限（另有阻尼项和关节安全约束）。这直接检验抗积分饱和/抬升不足与阻尼权衡。
- 位姿参考导纳 r2：平移 K ∈ {60, 95, 150, 240} N/m，ζ ∈ {0.7, 1.2}，Krot = 4K/95。质量 0.55 kg、惯量 0.065，其余 offset/velocity/action 限制保持原样。这检验虚拟位移大小与恢复速度的权衡。

开发条件固定为原 seed 9300/9301/9302 的 angle、height、payload 三元组；不能改变任务、0.2 mm 穿透门、接触/脱离门、solver 或仿真步长帮助某个候选通过。

## 测量与选择

使用统一的独立物理子步测量 wrapper；先验证它不改变任何原始 rollout 轨迹。保存三项主指标：25 Hz waypoint 位置 RMSE、物理子步实际关节 actuator torque 绝对峰值、物理子步末端线速度范数峰值。阶段与接触指标另报。实际力矩与更新后速度的时间戳语义不能混淆。

每家族只在全部 24 回合执行完成且指标有限后选一个候选：

1. 最大化完整 panel gate 通过数。
2. 再最大化任务通过数。
3. 对同一候选集合内三项回合均值分别由小到大取平均并列名次，最小化三项名次之和；此规则单位无关，但不是物理代价函数。所有候选的原始值与 Pareto 权衡仍需完整展示。
4. 完全并列按配置 ID 字典序决定，保证可复算。

若所有候选完整 gate 均失败，仍可保留上述规则的开发候选用于诊断，但必须标为“未达到可靠 baseline 验收”，不能称其最佳有效控制器。发现实现错误则保留本轮错误，修复后以新协议版本重跑全部受影响候选；不得只重跑看起来有希望的参数。

## 执行与证据

所有源文件与协议在服务器隔离快照运行，保留 hash、命令、原始 JSON/NPZ、测量 sidecar、退出状态、模型 MJB hash。最多 4 个服务器仿真 worker，待统一测量与 ESN 诊断队列结束后再启动，避免重复占用。不得因本机 RTX 5080 不适合单环境 MuJoCo 步进而盲目提高并行导致内存溢出。
