# 接触阶段、穿透门余量与共同误差窗口诊断

本报告仅分析已归档数据，没有执行mj_step、重跑任何回合、增加服务器worker、改验收门或删除失败。五方法六条件的冻结结果仍以[固定预算报告](CLASSICAL_FIXED_BUDGET_VALIDATION_20260923.md)为准。新增工具为 `tools/audit_contact_margin_history_20260924.py`，完整逐回合数值、原始输入hash与18000帧几何查询结果保存在[同名JSON](CONTACT_MARGIN_HISTORY_DIAGNOSIS_20260924.json)。

## 1. 新teacher-history配对确实改变了接触开始

代码链可直接追溯：`run_primitive_teacher_v7_20260917.py` 在任务达到请求阶段时写 `PUSH_ROD_START_S`；`audited_velocity_env.py` 每控制更新读取该时间，计算杆的smoothstep位移并写 `data.ctrl[push_rod_ctrl]`。因此不是仅改变日志中的event标签。

新协议显式固定了push/ball目标坐标，避免请求阶段的默认几何目标发生变化。每个fixture的approach/loaded_lift编译模型SHA256相同，使用同一个固定teacher（按train ID字典序选择 `push_00000`），没有按这些结果重新选择teacher。归档中的实际首次接触如下：

|---|---:|---:|---:|---:|
| train9600 | 0 | 0.50755 / 0 | 2.40 | 2.87235 / 3 |
| train9601 | 0 | 0.43510 / 0 | 2.40 | 2.86720 / 3 |

六条approach首次接触均未持物，六条loaded首次接触均已持物；实际杆首次接触与主contact首次时间一致。配对的观测、action、轨迹、阶段序列均确实不同，观测首次差异记录出现在0.48–0.56s。观测发生在控制前、记录时间在控制后，不能把这40ms记录时间当作精确物理因果延迟。

这个设计支持“同几何、固定teacher下，改变外部扰动开始阶段”的诊断。它不能单独识别“ESN记忆造成失败”：两组接触时的机器人位置、负载、夹爪状态、到结束的剩余时间和后续状态分布也不同。杆press=0.5s、stroke=0.18m、force limit=12N、hold=1000000s；所以这是持续推杆开始时刻干预，不是相同短脉冲加上不同记忆历史。全部12条teacher任务失败，不能直接当作可靠成功示范库，也不能因失败就删除它们。

`offline_metrics` 在teacher实际访问的48D观测上逐序列运行冻结MLP/ESN，并验证teacher标签重放；它评估的是状态条件下的模仿误差。离线预测没有控制机器人，不能作为学生闭环成功率。接触mask来自25Hz力样本并前移一帧，只是稀疏接触代理，不是完整子步接触占比。正负方向冲突还需保留有效teacher分量阈值和分母。

杆接触总时长从每40ms记录的“力>0.05N子步数×50μs”重算，与原JSON逐条一致，全部位于loaded-lift阶段3。稀疏查询中存在穿透的28条，其稀疏峰也在阶段3；阻抗9400/9401的25Hz姿态连正穿透都未捕获。**原始全子步穿透峰的精确发生时刻、对应机器人geom和越门持续时间没有保存，不能从以上统计补写出来。** 原审计对深度没有0.05N过滤，因此“有力接触都在阶段3”也不能严谨替代“全子步深度峰发生在阶段3”的证据。

### 保存数据能回答什么

| 数据 | 已保存口径 | 可得结论 | 不能得到 |
|---|---|---|---|
| rollout.json contact stats | 每障碍全物理步最大深度；有力接触首次/末次/累计时长；参与body集合 | 最大深度来自哪个障碍、原门余量、累计接触时间 | 深度峰的精确时刻/机器人geom；深度越门持续时间 |
| contact_samples.npz | 每40ms每障碍接触子步时长与力峰 | 接触集中在哪些阶段/40ms区间、区间力峰 | 区间内深度序列；力峰与深度峰是否同时 |
| physics_states.npz | 每40ms末尾qpos/qvel/ctrl | 在已保存姿态上重新查询碰撞几何 | 两个保存时刻之间的最大深度 |
| substep_metrics.npz | 每50μs末端误差/twist、实际actuator矩、时间和阶段 | 原三项物理指标与阶段误差 | qpos、逐接触dist、solver状态或完整接触几何 |

JSON里的 `sparse_above_gate_occupancy_proxy_s` 和最长活跃bin跨度仅为样本占用代理，不是精确持续时间；此批均为0不等于原全子步越门持续0秒。

## 3. 目前不能把越门归结为数值误差

使用本机已经存在的MuJoCo **3.11.0**（与服务器一致）加载原MJB，只在保存的qpos上执行 `mj_kinematics` 和 `mj_collision`，共30×600=18000帧，没有求解动力学或积分。robot audit集合、杆运行期碰撞mask均与原逻辑一致；未保存mocap运动的 `moving_obstacle_geom` 不参与查询结论。三个代表姿态的接触对/距离与 `mj_fwdPosition` 完全相同，qpos不变。

这18000帧中没有一帧超过0.2mm，最大仅0.045953mm（导纳9401，3.08s，杆×link7，阶段3）。这证明当前保存姿态查询未复现原50μs峰值；它兼容“短瞬态被漏采”“物理步内的接触求值时序差异”“碰撞算法敏感”等解释，**不能证明其中任何一个就是根因**。原仿真为aarch64、本次查询为x86_64；版本与模型一致也不保证跨平台碰撞数值逐位相同，因此查询不替代原在线审计。

进一步仅在scratch模型切换NativeCCD，对相同保存姿态重复几何查询：深度最大差2.029μm，没有采样点发生门判定翻转。该差量与部分门余量同量级，但由于没有峰值时刻的qpos，不能外推为原22条失败都属于CCD误差，更不能用scratch几何结果替换冻结动力学结果。原模型禁用NativeCCD；Newton迭代上限1000、求解容差1e-10、CCD迭代上限1000/容差1e-10、dt=50μs。数值容差不是物理穿透误差上界，迭代上限大也不等于每步都收敛。

模型中的solimp宽度0.0002m恰与穿透门0.2mm相同，但solimp宽度是接触阻抗随距离变化的参数，不是误差容忍区间或允许“碰撞漏过”的规则。没有步长收敛与峰时接触证据前，不能把这一数值相同解释为通过或失败的充分原因。

可以独立确认的控制问题仍存在：阻抗4/6杆接触时长不足0.3s；ESN5/6终点任务失败，误差44.7–80.4mm；VMC9405物体抬升不足且终点误差203.6mm。它们与微米级穿透判定不是同一个问题，即使以后解释了穿透峰也不会自动消失。

## 4. 补充共同时间/目标窗口，保留冻结主指标

原位置RMSE相对状态机waypoint，阶段切换时刻随控制器变化，Z和loaded-lift贡献约96–99%。因此需要补充共同目标窗口；不能把事后生成的连续轨迹误差拿来覆盖已冻结的25Hz选参指标或物理子步主表。

本次只使用既有25Hz trace，验证每个fixture的五方法在**2.64–24s**全部处于阶段3，535个共同样本的目标均严格等于 `[0.54, 0, 0.785]m`。另外固定共同末6秒 `(18,24]s`，150样本，分开计算XY和Z。窗口为本次事后诊断，不参与选择、reward或论文预声明成绩；所有失败照常纳入。

## 5. 可执行下一步：先补证据，再谈重训或改门

本轮未启动以下实验；这是面向下一版本的具体方案。

1. **增加非干预接触sidecar。** 在原mj_step后、原audit读取同一live contact的位置，记录每步/每障碍max(−dist)、峰值geom1/geom2/body、接触法向力、stage、time；累计超过0.18/0.19/0.20/0.21mm的步数和最长连续段，完整保留原0.2mm验收。阈值邻域统计只解释余量，不产生新获胜者。保存原峰值与所有0.19mm以上事件的qpos、qvel、ctrl、qacc_warmstart、mocap及solver_niter/残差摘要，明确求值状态与步末状态的差别。需要精确几何复核时保留contact求值所对应的步前状态，而非仅步末qpos。
2. **先确认测量不改变轨迹。** 使用新输出和源码快照，对原固定fixture/方法做instrumentation开关对照，18个原trace数组逐元素相等后再接受sidecar。已完成的106条保持原样，不在旧目录补写假造子步深度。
3. **如获准开展数值诊断，预先固定小矩阵。** 可选VMC、MLP、ESN在9400/9403这两个原验证条件，固定控制器及全部任务参数；3×2×{50,25μs}=12回合，用来检查门附近的步长敏感性，不重新评分/选模。保持相同控制更新周期；分别报原门、深度余量、越门持续、task/rod duration，以及不同dt导致的轨迹变化。原50μs只有在相同运行平台下恢复原轨迹后才可作为收敛参照。若继续NativeCCD动力学比较，需要单独声明它改变了碰撞计算算法，不能与只缩小dt混在一个因果解释里。
4. **峰时固定状态几何交叉检查。** 用步骤1保存的完整峰时状态，在同版本scratch中比较原CCD/NativeCCD与精确geomDistance。先判断距离查询差异，再观察动力学时间离散差异；只在普通25Hz姿态上比较不足以解决当前问题。没有实际测到误差界前，不给“0.2mm±ε可忽略”的结论。
5. **新的连续reference另立协议。** 如论文要测轨迹跟踪，应在跑新验证前固定共同初末位姿、时长、速度/加速度约束与时间锚点，使用共同连续reference；同时保留任务完成、接触/释放与安全门。可以另报接触开始后固定时长的XY让位/恢复、Z目标进度，但必须说明事件对齐是内生的，窗口时长也不能随某个方法的失败截短。优先沿用已核实的共同阶段窗口解决当前解释问题，不制造一个事后有利的平滑参考。
