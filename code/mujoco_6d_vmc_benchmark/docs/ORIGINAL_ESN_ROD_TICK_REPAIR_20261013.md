## 修复了什么

`scripts/audited_velocity_env.py` 的 direct_esn/twist 路径在策略步开始时，
从上一拍 `_last_policy_wbc_scale` 设置WBC反馈系数；随后更新当前动作，并将关节合成
`wbc_scale` 中性化为1以避免重复减速。结果是当前笛卡尔残差已经执行，反馈系数却仍使用
前一个40ms策略步的值。实测13,750个伺服步中78.98%与当前过滤动作不同，最大差0.16。

新增 `tools/feedback_tick_contract_20261013.py` 在每个4ms物理伺服步前同步当前已过滤系数，
不增加ESN更新次数，不插值、不改增益、不加摩擦前馈、不改合成scale=1；
记录真正被WBC消费的系数、名义/残差/实际速度与关节指令，而非仅记录请求值。
此错位也存在于原生运行代码，因此不能称其为旧场景迁移独有问题或唯一原因。

只登记两个55秒回合：A为原时序加记录，B仅同步当前系数。二者均沿用上一轮
continuous reference，未采用payload绕杯、伺服插值或摩擦前馈方案。
A与此前未加记录的回合在time/qpos/qvel/observation/action/reservoir_state上逐值一致；
B的13,750伺服步错拍率和系数误差均为0，残差同拍且没有双重缩放。

## 为什么不能称为“被棍子撞坏了储备池”

1. A首次棍接触前2秒，50个策略采样中原始x请求翻转47次。诊断记录中的球/人手/棍/杯/柱
   五类接触均为0。振荡在棍接触之前已有，不能全部归因于棍冲击；这也不等于证明所有物理接触均不存在。
2. 相同checkpoint的原生成功002回合曾承受282.148N棍峰力，但路径、姿态和事件时序不同。
   不能据此认为当前61.774N必然安全，只能说明峰力单一数值不足以解释差异。
3. 离线诊断在棍结束后以零状态重放**相同已记录观测**：A的动作差最终5.64e-8，
   状态差7.57e-8，约20秒后后续动作差始终小于1e-4；B也收敛。
   实际控制从未清空储备池。这仅说明给定相同输入时没有永久状态损坏证据，
   不证明真实闭环可以通过重置恢复，也不是部署重置的依据。
4. 固定前一拍储备池、其他观测不变，有限差分检查Fx到下一拍预裁剪vx读出的局部灵敏度。
   A的12–18秒约16.7%采样为负，B和原生回合该窗口均无负值。
   这是条件局部响应，不是物理因果干预或闭环稳定性证明，不能据此改符号或调读出。

当前证据支持继续审查“本体负载估计—策略响应—名义控制/速度伺服”的闭环耦合，
而不是假设棍推永久损坏网络。上一轮也已有接触后公共速度跟踪不足证据。
冻结参数的限制下，本轮不新增按单回合调滤波/增益的补丁，不做成功筛选。
