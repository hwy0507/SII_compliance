# Four-method multi-contact benchmark protocol — 2026-08-21

## Objective

Produce one directly comparable MuJoCo result table for: (i) the nominal
PaperMPC controller from the original paper, (ii) the analytic VMC torque
residual baseline, (iii) a memoryless MLP behaviour-cloning baseline, and
(iv) the proposed Direct ESN.  This protocol is deliberately not an ESN
search: the proposed ESN and VMC settings below are frozen before this work.

## Common environment and metrics

All rollouts use the PaperMPC nominal WBC backend, unchanged FR3 torque
limits, the same residual safety clamp and success criterion.  The contact
fixture is a `positive_y`, finite-mass, ellipsoidal `hand_proxy` driven by a
damped slide and force-limited position servo.  For every seed and fixture
index, all methods use the exact same fixture generated by
`fixture(seed * 6151 + fixture_index + 1)`.  Physical randomization ranges
are emitted into every raw JSON row.

The table will include success, at-grasp pose error, post-impact peak pose
error, peak robot--impactor force, peak torque, contact bouts, hard-limit
events, and recovery time.  It will also report matched ESN-minus-baseline
fixture-level and seed-level bootstrap confidence intervals.  Failed trials
are retained in the continuous metrics; there is no success-only filtering.

## Frozen comparators

| Method | Fixed policy and residual budget |
|---|---|
| Original paper method | PaperMPC nominal controller with a zero compliance residual. The 5% environment residual scale has no behavioural effect because the emitted action is identically zero. |
| VMC | Previously validation-selected analytic spring/carriage torque residual: `k_translation_base=1.0`, budget 2%. No reselection. |
| Proposed ESN | `/home/arm1/vmc_mujoco_runtime/outputs/paper_mpc_multicontact_multiscale_cem_20260821/esn_multiscale_cem.npz`, budget 5%. It is `successful-only multi-contact BC + fixed 320-unit fast--slow reservoir + train-only CEM bounded readout-row gains`; no online learning or exploration. |

The learned deployment observation contract is identical for MLP and ESN:
`q(7), qdot(7), nominal_twist(6), pose_error(6), wbc_twist_error(6)`.  Neither
gets force/contact, fixture/geometric parameters, approach-direction labels,
time-to-contact, or future information.

## MLP baseline selection

The MLP is strictly behaviour cloning, trained from the exact same 18
successful contact expert traces (10 negative-y rod, 8 positive-y hand proxy)
and one neutral no-contact trace as the multi-contact ESN bootstrap.  The two
failed hand traces, `positive_y_hand_03.npz` and `positive_y_hand_07.npz`, are
excluded from both BC datasets.  Actions are converted using recorded
provenance from each trace budget to the common 5% deployment action unit:

`clip(action_trace * trace_budget / 0.05, -1, 1)`.

The only predeclared MLP candidates are hidden width `{64, 128}` and training
seed `{20261501, 20261502}` (four candidates, all with the same fixed 400
epoch maximum, Adam settings and training data).  They are evaluated only on
validation seeds `20261511–20261515`, four matched fixtures per seed.  Select
the MLP by maximum validation success count, then lower mean at-grasp error.
This selection does not trigger any VMC/ESN changes.

## One held-out four-method cohort

After recording the MLP selection, run exactly one held-out cohort on seeds
`20261516–20261525`, four fixtures per seed (40 matched rollouts per method).
No test seed may be used for training, CEM, parameter selection, or any
rerun-based tuning.  The expected conclusion scope is limited to this declared
positive-y finite-mass hand-proxy distribution; it is not evidence of automatic
cross-direction/geometric OOD generalization or real-robot performance.
